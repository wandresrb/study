<Lead>
C es el terreno donde clangd brilla: análisis preciso, ir a definición a través de cabeceras y diagnósticos del compilador en tiempo real. La clave está en que clangd sepa cómo compilas tu proyecto.
</Lead>

<Objetivos>

- Configurar clangd y por qué necesita `compile_commands.json`.
- Generar esa base de datos con Bear o CMake.
- Inlay hints y ajustes finos de clangd.
- Depurar C con codelldb y nvim-dap.

</Objetivos>

## clangd ya está instalado

En la lección 2.1 añadiste `clangd` a `ensure_installed` de Mason, así que ya se habilita al abrir un `.c`. Puedes afinarlo con un override:

```lua title="lua/plugins/lang-c.lua"
return {
  "neovim/nvim-lspconfig",
  opts = function()
    vim.lsp.config("clangd", {
      cmd = {
        "clangd",
        "--background-index",
        "--clang-tidy",          -- integra clang-tidy (linter potente)
        "--header-insertion=iwyu",
        "--completion-style=detailed",
        "--function-arg-placeholders",
      },
      init_options = { fallbackFlags = { "-std=c17" } },
    })
  end,
}
```

<Callout type="info" title="Este archivo solo añade config">
Como `nvim-lspconfig` ya se instala en `lua/plugins/lsp.lua`, aquí solo reabrimos su spec para inyectar la config de clangd. También podrías poner el `vim.lsp.config("clangd", ...)` directamente en el archivo de LSP. Cualquiera de las dos formas vale.
</Callout>

## El corazón: compile_commands.json

clangd necesita saber **con qué flags** compilas cada archivo (includes, defines, estándar). Esa información vive en un `compile_commands.json` en la raíz del proyecto. Sin él, clangd adivina y verás falsos errores en los `#include`.

### Con CMake (lo genera solo)

```bash
cmake -S . -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
# enlaza el json a la raíz para que clangd lo encuentre
ln -s build/compile_commands.json .
```

### Con Makefiles: usa Bear

`bear` "envuelve" tu compilación y captura los comandos reales:

```bash
# macOS: brew install bear   ·   Debian: apt install bear
bear -- make
```

<Callout type="tip" title="Proyecto de un solo archivo">
Para pruebas rápidas de un `.c` suelto, clangd usa flags por defecto (el `fallbackFlags` de arriba). Para cualquier proyecto real, genera el `compile_commands.json`: es la diferencia entre clangd útil y clangd frustrante.
</Callout>

## Formateo con clang-format

Ya configuraste `c = { "clang_format" }` en conform (lección 2.4). Instala el binario con `:Mason` (`clang-format`). Personaliza el estilo con un archivo `.clang-format` en la raíz:

```yaml title=".clang-format"
BasedOnStyle: LLVM
IndentWidth: 4
ColumnLimit: 100
AllowShortFunctionsOnASingleLine: None
```

## Debugging con codelldb

`codelldb` (instalado por mason-nvim-dap en la lección 2.4) es el adaptador. Define una configuración de debug para C:

```lua title="lua/plugins/lang-c.lua (añadir al config de dap)"
local dap = require("dap")
dap.adapters.codelldb = {
  type = "server",
  port = "${port}",
  executable = {
    command = vim.fn.exepath("codelldb"),
    args = { "--port", "${port}" },
  },
}
dap.configurations.c = {
  {
    name = "Lanzar ejecutable",
    type = "codelldb",
    request = "launch",
    program = function()
      return vim.fn.input("Ruta al ejecutable: ", vim.fn.getcwd() .. "/", "file")
    end,
    cwd = "${workspaceFolder}",
    stopOnEntry = false,
  },
}
```

Compila con símbolos de depuración (`gcc -g -o programa programa.c`), pon un breakpoint con `<leader>db`, y arranca con `<leader>dc`.

<Callout type="dios" title="clang-tidy es tu revisor gratis">
Con `--clang-tidy` activado, clangd te avisa de bugs sutiles: fugas de memoria potenciales, comparaciones peligrosas, usos tras liberar. Configúralo con un `.clang-tidy` en la raíz activando checks (`bugprone-*`, `performance-*`). Es como tener un revisor senior mirando cada línea que escribes.
</Callout>

<Reto title="C con superpoderes">
1. Genera `compile_commands.json` en un proyecto C (CMake o Bear).
2. Abre un `.c`: navega con `gd` a través de un `#include` hasta la definición.
3. Introduce un error de tipos y confirma que clangd lo marca al instante.
4. Compila con `-g`, pon un breakpoint y depura con `<leader>dc` + `<leader>du`.
</Reto>

<Lead>
Aquí está la habilidad clave del Arquitecto: tomar una base ajena y hacerla tuya sin romperla. LazyVim está diseñada para que la modifiques con elegancia — override, no parche. Estas son las cuatro operaciones que necesitas.
</Lead>

<Objetivos>

- Sobreescribir las `opts` de un plugin de LazyVim.
- Añadir tus propios plugins y desactivar los que no quieras.
- Poner tus opciones y keymaps que ganan a los de la distro.
- Cambiar el tema (colorscheme).

</Objetivos>

## La regla de oro: override, no editar la distro

Nunca edites los archivos internos de LazyVim. En su lugar, crea un archivo en `lua/plugins/` con una spec del mismo plugin: LazyVim **fusiona** tu configuración con la suya. Tus cambios sobreviven a las actualizaciones.

## 1) Sobreescribir las opciones de un plugin

Devuelve una spec con el mismo repo y tus `opts`. LazyVim hace un *deep merge* con las suyas:

```lua title="lua/plugins/override.lua"
return {
  -- cambia opciones de un plugin que YA trae LazyVim
  {
    "nvim-treesitter/nvim-treesitter",
    opts = {
      ensure_installed = { "swift", "zig" }, -- se AÑADEN a las de LazyVim
    },
  },
}
```

¿Necesitas lógica, no solo fusionar? Usa `opts` como función y recibes las opciones actuales para modificarlas:

```lua title="lua/plugins/override.lua"
return {
  {
    "nvim-lualine/lualine.nvim",
    opts = function(_, opts)
      -- modifica lo que LazyVim ya configuró
      table.insert(opts.sections.lualine_x, "  " .. os.date("%H:%M"))
      return opts
    end,
  },
}
```

## 2) Añadir tus propios plugins

Igual que en tu config a mano: un archivo en `lua/plugins/` con la spec. Se suma a la base de LazyVim:

```lua title="lua/plugins/extra.lua"
return {
  { "folke/zen-mode.nvim", cmd = "ZenMode", opts = {} },
}
```

## 3) Desactivar un plugin de LazyVim

Ponle `enabled = false`:

```lua title="lua/plugins/disable.lua"
return {
  { "folke/flash.nvim", enabled = false }, -- fuera flash, prefiero otra cosa
}
```

## 4) Opciones y keymaps que ganan

LazyVim carga **tus** `lua/config/options.lua` y `keymaps.lua` **después** de los suyos, así que lo tuyo prevalece:

```lua title="lua/config/options.lua"
-- se fusiona con las opciones de LazyVim; lo tuyo manda
vim.opt.relativenumber = true
vim.opt.scrolloff = 10
vim.g.snacks_animate = false
```

```lua title="lua/config/keymaps.lua"
local map = vim.keymap.set
map("n", "<leader>ww", "<cmd>w<cr>", { desc = "Guardar rápido" })

-- ¿quitar un keymap que pone LazyVim? bórralo:
-- vim.keymap.del("n", "<leader>xx")
```

<Callout type="tip" title="Descubre los atajos de LazyVim">
LazyVim trae which-key configurado: pulsa `<leader>` y espera para ver TODO su mapa de atajos (con sus grupos: `<leader>f` buscar, `<leader>g` git, `<leader>c` código…). Antes de crear un keymap, comprueba si ya existe uno; así no duplicas ni pisas nada sin querer.
</Callout>

## Cambiar el tema

LazyVim usa Tokyo Night por defecto. Para poner Catppuccin (o cualquiera), instala el tema y dile a LazyVim que lo use:

```lua title="lua/plugins/colorscheme.lua"
return {
  { "catppuccin/nvim", name = "catppuccin", opts = { flavour = "mocha" } },
  {
    "LazyVim/LazyVim",
    opts = { colorscheme = "catppuccin" },
  },
}
```

<Callout type="dios" title="La mentalidad override">
Todo en LazyVim se personaliza declarando lo que quieres **distinto**, no reescribiendo lo que ya funciona. Un archivo por cambio, cada uno diciendo "de este plugin, cambia esto". Tu carpeta `lua/plugins/` se convierte en la lista de tus decisiones sobre la base. Cuando LazyVim se actualice, tus overrides seguirán en pie porque nunca tocaste sus tripas. Así se dobla una distro sin romperla.
</Callout>

<Reto title="Hazla tuya">
1. Cambia el tema a Catppuccin con un override.
2. Añade un plugin nuevo (p. ej. zen-mode) en `lua/plugins/`.
3. Desactiva un plugin que no uses con `enabled = false`.
4. Añade una opción propia en `options.lua` y confirma que prevalece.
5. Pulsa `<leader>` y explora el mapa de atajos de LazyVim antes de crear los tuyos.
</Reto>

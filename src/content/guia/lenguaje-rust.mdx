<Lead>
Rust en Neovim no se configura con el LSP genérico: se usa rustaceanvim, que envuelve rust-analyzer y le añade todo lo que hace especial a Rust — ejecutar tests inline, expandir macros, depurar con un comando.
</Lead>

<Objetivos>

- Por qué rustaceanvim y no `rust_analyzer` por lspconfig.
- Runnables, debuggables y expand macro.
- crates.nvim para gestionar dependencias en `Cargo.toml`.
- Formateo y debugging integrados.

</Objetivos>

## rustaceanvim, no rust_analyzer

<Callout type="danger" title="No configures rust_analyzer a mano">
Si añades `rust_analyzer` a Mason **y** usas rustaceanvim, ambos intentan adjuntar el mismo servidor y chocan. **Regla:** con rustaceanvim, NO pongas `rust_analyzer` en `ensure_installed`. rustaceanvim gestiona rust-analyzer por su cuenta. (El viejo `rust-tools.nvim` está archivado; rustaceanvim es su sucesor.)
</Callout>

rustaceanvim se configura solo con existir; no lleva `.setup()`. Basta con definir opciones en una variable global:

```lua title="lua/plugins/lang-rust.lua"
return {
  "mrcjkb/rustaceanvim",
  version = "^6",
  lazy = false, -- el propio plugin ya es lazy por filetype
  config = function()
    vim.g.rustaceanvim = {
      server = {
        on_attach = function(_, bufnr)
          local map = function(k, fn, desc)
            vim.keymap.set("n", k, fn, { buffer = bufnr, desc = desc })
          end
          -- Acciones específicas de Rust vía el comando :RustLsp
          map("<leader>rr", function() vim.cmd.RustLsp("runnables") end, "Rust: runnables")
          map("<leader>rd", function() vim.cmd.RustLsp("debuggables") end, "Rust: debuggables")
          map("<leader>rm", function() vim.cmd.RustLsp("expandMacro") end, "Rust: expandir macro")
          map("<leader>rc", function() vim.cmd.RustLsp("openCargo") end, "Rust: abrir Cargo.toml")
          map("K", function() vim.cmd.RustLsp({ "hover", "actions" }) end, "Rust: hover con acciones")
        end,
        default_settings = {
          ["rust-analyzer"] = {
            cargo = { allFeatures = true },
            checkOnSave = true,
            check = { command = "clippy" }, -- clippy en cada guardado
            procMacro = { enable = true },
          },
        },
      },
    }
  end,
}
```

## Runnables y debuggables

Aquí está la magia de rustaceanvim:

<Cards>
  <Card icon="▶️" title="Runnables">
    `<leader>rr` lista lo ejecutable en el contexto: `main`, un test concreto, un ejemplo. Elige y corre, sin salir al terminal.
  </Card>
  <Card icon="🐞" title="Debuggables">
    `<leader>rd` lanza el mismo target bajo el debugger (usa codelldb + nvim-dap de la lección 2.4). Breakpoints en Rust sin configurar nada más.
  </Card>
  <Card icon="🔬" title="Expand macro">
    `<leader>rm` expande la macro bajo el cursor y te muestra el código generado. Oro puro para entender `derive` y macros procedurales.
  </Card>
  <Card icon="💡" title="Hover con acciones">
    `K` muestra la doc y, encadenado, las code actions agrupadas por categoría en una UI que el LSP nativo no ofrece.
  </Card>
</Cards>

## crates.nvim: dependencias en Cargo.toml

Gestiona versiones de crates con completado, información de versiones y actualizaciones dentro de `Cargo.toml`:

```lua title="lua/plugins/crates.lua"
return {
  "saecki/crates.nvim",
  event = { "BufRead Cargo.toml" },
  opts = {
    completion = { crates = { enabled = true } },
    lsp = { enabled = true, actions = true, completion = true, hover = true },
  },
}
```

Ahora en `Cargo.toml` ves qué versión es la última, qué features tiene un crate y puedes actualizar con una code action.

## Formateo

`rustfmt` viene con la toolchain de Rust. Ya lo pusiste en conform (`rust = { "rustfmt" }`), así que se formatea al guardar. rustaceanvim también respeta `rustfmt.toml`.

<Callout type="dios" title="El bucle de Rust en Neovim">
Escribe → guarda (clippy te revisa al instante) → `<leader>rr` para correr el test bajo el cursor → si falla, `<leader>rd` para depurarlo con breakpoints → `<leader>rm` si una macro te confunde. Todo sin tocar el ratón ni cambiar de ventana. Este bucle cerrado es más rápido que cualquier IDE gráfico de Rust.
</Callout>

<Reto title="Rust en su salsa">
1. Añade rustaceanvim (sin `rust_analyzer` en Mason) y crates.nvim.
2. Abre un proyecto Cargo. Sobre un test, pulsa `<leader>rr` y córrelo.
3. Haz que el test falle y depúralo con `<leader>rd`.
4. Sobre un `#[derive(...)]`, usa `<leader>rm` para ver qué genera.
5. En `Cargo.toml`, mira las versiones disponibles de un crate con crates.nvim.
</Reto>

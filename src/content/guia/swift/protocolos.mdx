<Lead>
Si en otros lenguajes la reutilización se basa en heredar de clases, en Swift se basa en protocolos. Un protocolo es un contrato: "quien cumpla esto, puede hacer aquello". Es más flexible que la herencia y funciona con structs, enums y clases por igual.
</Lead>

<Objetivos>

- Definir protocolos y conformar a ellos.
- Extensiones de protocolo con implementaciones por defecto.
- Programación orientada a protocolos (POP).
- Protocolos del sistema: Identifiable, Codable, Comparable.

</Objetivos>

## Un protocolo es un contrato

Define **qué** debe ofrecer un tipo, sin decir cómo:

```swift
protocol Describible {
    var descripcion: String { get }
    func resumen() -> String
}
```

Cualquier tipo puede **conformar** al protocolo implementando lo que pide:

```swift
struct Libro: Describible {
    let titulo: String
    var descripcion: String { "Libro: \(titulo)" }
    func resumen() -> String { descripcion }
}
```

Un `struct`, un `enum` o una `class` pueden conformar al mismo protocolo. La capacidad no depende de la jerarquía de tipos.

## Extensiones de protocolo: comportamiento compartido

Aquí está el superpoder. Puedes dar una **implementación por defecto** a los métodos de un protocolo mediante una extensión:

```swift
extension Describible {
    func resumen() -> String {
        "→ \(descripcion)"   // implementación por defecto para TODOS
    }
}

struct Pelicula: Describible {
    let titulo: String
    var descripcion: String { "Película: \(titulo)" }
    // no hace falta implementar resumen(): hereda el de la extensión
}
```

Ahora cualquier tipo que conforme a `Describible` obtiene `resumen()` gratis, y puede sobreescribirlo si quiere.

<Callout type="dios" title="Composición sobre herencia">
Con clases, para compartir código heredas de una superclase, y acabas con jerarquías rígidas y frágiles (el "problema del diamante", clases base infladas…). Con protocolos + extensiones, un tipo **compone** capacidades: conforma a `Identifiable`, a `Codable`, a `Comparable`, y obtiene comportamiento de cada uno, sin heredar de nada. Esto es la **programación orientada a protocolos**, la filosofía central de Swift. Piensa en "qué puede hacer" este tipo, no "qué es".
</Callout>

## Protocolos del sistema que usarás siempre

<Cards>
  <Card icon="🆔" title="Identifiable">
    Da a un tipo un `id` único. SwiftUI lo exige para listas: cada fila necesita identidad.
  </Card>
  <Card icon="📦" title="Codable">
    Convierte a/desde JSON automáticamente. Clave para redes (Nivel 5).
  </Card>
  <Card icon="⚖️" title="Comparable">
    Permite ordenar (`<`, `sorted()`) tus tipos.
  </Card>
  <Card icon="🔁" title="Equatable / Hashable">
    Comparar por igualdad y usar en Sets y claves de Dictionary.
  </Card>
</Cards>

```swift
struct Tarea: Identifiable, Codable {
    let id = UUID()
    var titulo: String
    var completada = false
}
```

Con solo declarar la conformidad, Swift **sintetiza** el código por ti (el `id`, la codificación JSON, la comparación…). Escribes el contrato; el compilador rellena lo mecánico.

<Callout type="tip" title="Restringe genéricos con protocolos">
Los protocolos brillan junto a los genéricos (próxima lección): puedes escribir una función que funcione con "cualquier tipo que sea `Comparable`", o "cualquier `Codable`". El protocolo es la restricción que da poder a lo genérico.
</Callout>

<Reto title="Piensa en capacidades">
1. Define un protocolo `Saludable` con un método `saludar()`.
2. Dale una implementación por defecto con una extensión.
3. Haz que una struct conforme sin implementar el método (usa el default) y otra que lo sobreescriba.
4. Crea una struct `Producto` que conforme a `Identifiable` y `Codable` con un `id = UUID()`.
</Reto>

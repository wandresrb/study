<Lead>
Para desarrollar para iOS necesitas dos cosas: un Mac y Xcode. Swift es el lenguaje; Xcode es el taller donde se construye todo — editor, simulador, depurador y la puerta a la App Store. Empecemos por montarlo bien.
</Lead>

<Objetivos>

- Instalar Xcode 26 y entender qué incluye.
- Conocer las piezas del ecosistema: Swift, SwiftUI, simulador.
- Escribir y ejecutar tu primer código Swift en un Playground.
- Los atajos de Xcode que usarás cada día.

</Objetivos>

## Qué necesitas

<Callout type="warn" title="iOS necesita un Mac">
El desarrollo para iOS/iPadOS/macOS requiere **macOS + Xcode**. Swift en sí es open source y corre en Linux y Windows, pero para compilar apps de Apple y usar el simulador necesitas un Mac. Es un requisito de Apple, no de Swift.
</Callout>

Instala **Xcode 26** desde la Mac App Store (o desde [developer.apple.com](https://developer.apple.com/xcode/)). Es una descarga grande (varios GB) porque incluye:

<Cards>
  <Card icon="✏️" title="El editor">
    Donde escribes Swift, con autocompletado, refactors y, en Xcode 26, asistente de IA integrado.
  </Card>
  <Card icon="📱" title="El Simulador">
    iPhones y iPads virtuales para probar tu app sin dispositivo físico.
  </Card>
  <Card icon="🐞" title="El depurador">
    Breakpoints, inspección de variables y el visor de jerarquía de vistas.
  </Card>
  <Card icon="📦" title="Los SDK">
    iOS 26, macOS, watchOS… las bibliotecas de Apple (SwiftUI, SwiftData, etc.).
  </Card>
</Cards>

<Callout type="info" title="Versiones (julio 2026)">
La toolchain de referencia es **Xcode 26** con **Swift 6.3**. El **SDK de iOS 26** ya es obligatorio para publicar. Todo en esta guía asume ese conjunto: Swift 6.3, SwiftUI e iOS 26.
</Callout>

## El ecosistema en una frase

- **Swift** es el lenguaje (tipos, funciones, concurrencia…).
- **SwiftUI** es el framework para construir interfaces de forma declarativa.
- **SwiftData** es para guardar datos.
- **Xcode** es la herramienta que junta todo y compila la app.

Los aprenderás en este orden: primero el lenguaje (Niveles 0–1), luego la interfaz (2–3), los datos (4), el mundo real (5) y publicar (6).

## Tu primer código: un Playground

Un **Playground** ejecuta Swift al instante, sin crear una app entera. Perfecto para aprender. En Xcode: `File ▸ New ▸ Playground`, elige "Blank", y escribe:

```swift
import Foundation

let nombre = "William"
print("¡Hola, \(nombre)!")

let numeros = [1, 2, 3, 4, 5]
let suma = numeros.reduce(0, +)
print("La suma es \(suma)")
```

Pulsa <KeyCap keys="Cmd R" /> (o el botón ▶). Verás la salida en la consola y los resultados de cada línea a la derecha. Ese `\(...)` dentro del string es **interpolación**: inserta el valor de una variable. Lo usarás constantemente.

<Callout type="tip" title="Swift Playgrounds (la app)">
En iPad o Mac existe también la app gratuita **Swift Playgrounds**, con cursos interactivos y la capacidad de publicar apps directamente. Es una forma estupenda de practicar el lenguaje sin la complejidad de Xcode.
</Callout>

## Atajos de Xcode imprescindibles

| Atajo | Acción |
|-------|--------|
| <KeyCap keys="Cmd R" /> | Compilar y ejecutar |
| <KeyCap keys="Cmd B" /> | Compilar (build) |
| <KeyCap keys="Cmd ." /> | Detener |
| <KeyCap keys="Cmd Shift O" /> | Abrir rápido cualquier archivo o símbolo |
| <KeyCap keys="Cmd /" /> | Comentar / descomentar |
| <KeyCap keys="Ctrl I" /> | Reindentar |
| <KeyCap keys="Cmd Shift K" /> | Limpiar (clean) |

<Callout type="dios" title="El primer reflejo: leer la consola">
Cuando algo falle —y fallará—, tu primer instinto debe ser **leer el error** en la consola y el panel de issues, no adivinar. Swift es un lenguaje muy explícito: sus mensajes de error suelen decirte exactamente qué tipo esperaba y qué recibió. Aprender a leerlos desde el día uno te ahorra horas.
</Callout>

<Reto title="Tu entorno, listo">
1. Instala Xcode 26 y ábrelo una vez para que termine de configurarse.
2. Crea un Playground en blanco.
3. Escribe un `print` con interpolación usando tu nombre.
4. Ejecútalo con <KeyCap keys="Cmd R" /> y confirma la salida.
5. Prueba <KeyCap keys="Cmd Shift O" /> para abrir algo rápido.
</Reto>

<Lead>
async/await es perfecto para "pide una cosa, espera una respuesta". Pero muchas fuentes emiten valores continuamente: la ubicación del GPS, mensajes que llegan, el progreso de una descarga. Para eso están los async streams: una secuencia de valores en el tiempo que recorres con un bucle.
</Lead>

<Objetivos>

- Qué es un `AsyncSequence`.
- Recorrer valores con `for await`.
- Crear tus propios flujos con `AsyncStream`.
- Cancelación y ciclo de vida.

</Objetivos>

## Un bucle sobre el tiempo

Un `AsyncSequence` es como un array cuyos elementos van llegando poco a poco. Lo recorres con `for await`, que espera cada valor:

```swift
for await ubicacion in gestorUbicacion.actualizaciones {
    print("Nueva posición: \(ubicacion)")
    // el bucle continúa cada vez que llega una ubicación nueva
}
```

El bucle no termina cuando "se acaban los datos ahora": se pausa esperando el siguiente valor, y sigue cuando llega. Ideal para fuentes vivas.

## Crear un flujo con AsyncStream

Envuelve cualquier fuente de eventos (un temporizador, un callback antiguo, un sensor) en un `AsyncStream`:

```swift
func contador() -> AsyncStream<Int> {
    AsyncStream { continuation in
        Task {
            for i in 1...5 {
                try? await Task.sleep(for: .seconds(1))
                continuation.yield(i)        // emite un valor
            }
            continuation.finish()            // termina el flujo
        }
    }
}

// consumirlo:
for await n in contador() {
    print(n)   // 1, 2, 3, 4, 5, uno por segundo
}
```

`yield` emite; `finish` cierra. Cualquier API basada en callbacks o notificaciones puede volverse un stream limpio y recorrible.

<Callout type="dios" title="El puente entre lo viejo y lo nuevo">
`AsyncStream` es tu herramienta para modernizar código: envuelves una API antigua basada en delegados o closures repetidos, y por fuera ofreces un `for await` elegante. En vez de esparcir lógica en métodos de callback desconectados, la concentras en un bucle legible. Muchas de las APIs del sistema (ubicación, notificaciones, `NotificationCenter`) ya ofrecen versiones async así. Reconocer cuándo algo "emite valores en el tiempo" y modelarlo como stream es una señal de madurez con la concurrencia.
</Callout>

## Cancelación

Los streams respetan la cancelación de tareas: si la `Task` que los consume se cancela (por ejemplo, la vista desaparece y su `.task` se cancela), el bucle `for await` termina de forma limpia. Por eso `.task` en SwiftUI y los streams se llevan tan bien:

```swift
.task {
    for await evento in fuente.eventos {
        procesar(evento)
    }
    // si la vista desaparece, el bucle se corta solo
}
```

<Callout type="tip" title="Comprueba la cancelación en bucles largos">
En trabajo largo dentro de una tarea, comprueba `Task.isCancelled` o llama a `try Task.checkCancellation()` de vez en cuando para salir pronto si ya no hace falta el resultado. Respetar la cancelación mantiene tu app eficiente: no gastes batería y datos en algo que el usuario ya dejó atrás.
</Callout>

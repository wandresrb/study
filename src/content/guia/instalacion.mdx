<Lead>
Antes de escribir una sola línea de config necesitas tres cosas: Neovim actualizado, un puñado de herramientas de línea de comandos que los plugins usan por debajo, y una Nerd Font para los iconos. Vamos a por ellas.
</Lead>

<Objetivos>

- Instalar Neovim 0.12 o superior en tu sistema.
- Instalar las dependencias clave: `git`, `ripgrep`, `fd`, compilador C y Node.
- Configurar una Nerd Font y elegir un buen emulador de terminal.
- Verificar todo con `:checkhealth` y hacer `vimtutor`.

</Objetivos>

## Instalar Neovim

<Callout type="warn" title="0.12 no es opcional en esta guía">
Confirma con `nvim --version` que tienes **0.12 o superior** (la serie estable actual es la 0.12.4). No es un capricho: el gestor de plugins integrado `vim.pack` es de 0.12, y la rama viva de `nvim-treesitter` exige 0.12 como mínimo. Con 0.11 media guía no te va a compilar. Los gestores de paquetes a veces van atrasados; en macOS, Homebrew suele estar al día.
</Callout>

### macOS (Homebrew)

```bash
# Neovim + herramientas que usarás sí o sí
brew install neovim git ripgrep fd fzf lazygit
# tree-sitter-cli lo exige la rama main de nvim-treesitter (lección 1.2)
brew install tree-sitter
# Node y Rust son necesarios para varios LSP y herramientas
brew install node rust
```

macOS ya trae compilador C (Xcode Command Line Tools). Si te falta:

```bash
xcode-select --install
```

### Linux (Debian/Ubuntu)

El repositorio oficial suele ir atrasado, y con 0.12 como mínimo eso importa. Usa un binario oficial:

```bash
# Opción recomendada: tarball oficial (siempre la última estable)
curl -LO https://github.com/neovim/neovim/releases/latest/download/nvim-linux-x86_64.tar.gz
sudo rm -rf /opt/nvim-linux-x86_64
sudo tar -C /opt -xzf nvim-linux-x86_64.tar.gz
# Añade esto a tu ~/.bashrc o ~/.zshrc
export PATH="$PATH:/opt/nvim-linux-x86_64/bin"

# Dependencias
sudo apt install git ripgrep fd-find build-essential curl tar
```

Y `tree-sitter-cli`, que la rama `main` de `nvim-treesitter` exige. **No lo instales con npm**: el propio proyecto lo desaconseja porque esa versión no siempre trae lo que necesita. Usa tu gestor de paquetes, o `cargo`:

```bash
cargo install tree-sitter-cli
```

Si prefieres un único ejecutable, la AppImage sigue publicándose en cada release:

```bash
curl -LO https://github.com/neovim/neovim/releases/latest/download/nvim-linux-x86_64.appimage
chmod u+x nvim-linux-x86_64.appimage
sudo mv nvim-linux-x86_64.appimage /usr/local/bin/nvim
```

### Windows

```powershell
winget install Neovim.Neovim
winget install BurntSushi.ripgrep.MSVC sharkdp.fd Git.Git
```

<Callout type="tip" title="WSL2, la vía cómoda en Windows">
Para desarrollo serio en Windows, instala Neovim dentro de **WSL2** (Ubuntu). Tendrás un entorno Linux real donde todos los plugins y LSP funcionan sin fricción.
</Callout>

## Dependencias clave y para qué sirven

<Cards>
  <Card icon="🔍" title="ripgrep (rg)">
    Búsqueda de texto ultrarrápida. La usan Telescope/Snacks para el "grep" global del proyecto.
  </Card>
  <Card icon="📁" title="fd">
    Búsqueda de archivos rápida, respetando .gitignore. Motor del buscador de ficheros.
  </Card>
  <Card icon="🌿" title="git">
    Imprescindible: `vim.pack` (el gestor integrado en 0.12) clona y actualiza con `git` por debajo. Sin él no hay plugins.
  </Card>
  <Card icon="🔨" title="Compilador C">
    Treesitter compila parsers y muchos plugins tienen partes nativas. `gcc`/`clang`.
  </Card>
  <Card icon="🌳" title="tree-sitter-cli">
    Lo exige la rama `main` de `nvim-treesitter` (0.26.1 o superior) para generar parsers. Por gestor de paquetes o `cargo`, **nunca por npm**.
  </Card>
  <Card icon="⬢" title="Node.js">
    Requerido por LSP de frontend (TypeScript, Tailwind, ESLint) y algunos plugins.
  </Card>
  <Card icon="🐙" title="lazygit">
    TUI de Git espectacular que integraremos dentro de Neovim en el Nivel 2.
  </Card>
</Cards>

## La Nerd Font (no la saltes)

Muchos plugins muestran iconos (archivos, Git, diagnósticos). Necesitas una **Nerd Font**: una fuente parcheada con miles de glifos. Sin ella verás cuadraditos `□`.

```bash
# macOS
brew install --cask font-jetbrains-mono-nerd-font
```

En Linux/Windows, descarga desde [nerdfonts.com](https://www.nerdfonts.com/) (JetBrainsMono, FiraCode o CaskaydiaCove son excelentes) y **configúrala como fuente en tu terminal**. Este paso se hace en el terminal, no en Neovim.

Neovim vive en tu emulador de terminal. Uno moderno con aceleración por GPU se nota:

<Cards>
  <Card icon="🐱" title="Kitty">

  </Card>
  <Card icon="⚡" title="WezTerm">

## Primer arranque y salud

Arranca Neovim con:

```bash
nvim
```

Verás la pantalla de bienvenida. Antes de nada, comprueba la salud del sistema. Escribe (en modo Normal) y pulsa Enter:

```vim
:checkhealth
```

Esto abre un informe: qué dependencias detecta, qué falta, versiones, providers. Revisa que no haya errores en rojo en lo esencial (git, ripgrep, fd, compilador). Los avisos sobre "providers" de Python/Ruby/Perl puedes ignorarlos si no los usas.

<Callout type="tip" title="Recarga sin salir al terminal">
Cuando empieces a tocar la config vas a reiniciar Neovim cien veces al día. En 0.12 no hace falta cerrar y volver a abrir: `:restart` levanta la sesión de nuevo con el código actualizado. Apúntatelo desde ya.
</Callout>

<Callout type="info" title="¿Dónde vive la config?">
Tu configuración irá en `~/.config/nvim/` (en Windows con nativo: `~/AppData/Local/nvim/`). El archivo raíz es `init.lua`. Aún no existe: lo crearemos en el Nivel 1.
</Callout>

## vimtutor: 30 minutos que lo cambian todo

Antes de seguir, haz el tutorial interactivo oficial. Es la mejor inversión de tiempo que harás. Desde tu terminal:

```bash
nvim +Tutor
```

Sigue las instrucciones dentro del propio documento durante 25–30 minutos. No lo saltes pensando "ya lo leeré": la memoria muscular solo se forma tecleando.

<Callout type="dios" title="Casi todo lo que falla al principio es una dependencia, no una config">
Merece la pena entender por qué esta lección existe, porque explica la mitad de los mensajes de "no me funciona" que verás en cualquier foro. Neovim no trae casi nada dentro: el buscador de archivos no busca, delega en `ripgrep` y `fd`; el gestor de plugins no clona, delega en `git`; Treesitter no genera parsers, delega en `tree-sitter-cli` y en tu compilador de C; los servidores de lenguaje son procesos externos que alguien tiene que instalar. Esa arquitectura es lo que hace al editor pequeño, rápido y portable, y es también la razón de que un fallo se manifieste casi siempre lejos de su causa: el picker aparece vacío y crees que el plugin está roto, cuando lo que pasa es que `fd` no está en el PATH. Interioriza el reflejo desde hoy: cuando algo no funcione, la primera pregunta no es "qué opción me falta" sino **"qué binario le falta al editor"**, y la respuesta la da `:checkhealth` en cinco segundos. Ese comando es la herramienta más infravalorada de Neovim, y quien lo ejecuta antes de buscar en Google se ahorra la mayoría de las tardes perdidas de las que se queja todo el mundo.
</Callout>

<Reto title="Checklist de instalación">
1. `nvim --version` muestra 0.12 o superior. ✅
2. `:checkhealth` no reporta errores críticos, y `git` aparece detectado. ✅
3. Tu terminal usa una Nerd Font (prueba: `echo ""` debe mostrar una carpeta 📁, no un cuadro). ✅
4. Completaste al menos la mitad de `nvim +Tutor`. ✅

Cuando tengas los cuatro, estás listo para la gramática de Vim.
</Reto>

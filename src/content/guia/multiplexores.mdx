<Lead>
Un multiplexor divide una terminal en paneles y ventanas, y mantiene tus sesiones vivas aunque cierres el terminal o se caiga la conexión. Combinado con Neovim, te da un espacio de trabajo persistente: editor, servidor, logs y tests, todo a la vez.
</Lead>

<Objetivos>

- Qué aporta un multiplexor y cuándo usarlo.
- tmux vs zellij: cuál elegir en 2026.
- Navegación transparente entre paneles y splits de Neovim.
- Sesiones y "sessionizers" para saltar entre proyectos.

</Objetivos>

## ¿Por qué un multiplexor?

<Cards>
  <Card icon="🪟" title="Paneles y ventanas">
    Editor arriba, servidor y logs abajo, tests al lado. Todo en una sola terminal.
  </Card>
  <Card icon="💾" title="Persistencia">
    Cierra el terminal, vuelve mañana y tu sesión sigue igual: procesos vivos, layout intacto.
  </Card>
  <Card icon="🗂️" title="Sesiones por proyecto">
    Una sesión por proyecto. Saltas entre ellas al instante sin perder el contexto.
  </Card>
</Cards>

## tmux vs zellij

<Cards>
  <Card icon="🧩" title="tmux">
    El veterano (v3.4). Basado en una tecla prefijo (`Ctrl-b`). Máxima potencia, scriptable, en todos lados. Curva más dura y config manual.
  </Card>
  <Card icon="✨" title="zellij">
    El moderno (v0.41+). Basado en modos con una barra que muestra las acciones disponibles. Productivo en minutos, detecta paneles de Neovim automáticamente.
  </Card>
</Cards>

<Callout type="tip" title="¿Cuál elijo?">
Desarrollas en tu propia máquina y valoras descubribilidad → **zellij**. Trabajas mucho por SSH en servidores, quieres scripting y ubicuidad → **tmux**. Ambos son excelentes; aquí configuramos la navegación fluida con Neovim en los dos.
</Callout>

## Navegación transparente (la pieza clave)

El problema: dentro de tmux/zellij, <KeyCap keys="Ctrl-h/j/k/l" /> debería moverte entre paneles; dentro de Neovim, entre splits. Sin integración, chocan. La solución hace que **las mismas teclas** funcionen sin pensar: si hay un split de Neovim en esa dirección, salta a él; si no, al panel del multiplexor.

### Con tmux: vim-tmux-navigator

```lua title="lua/plugins/tmux-nav.lua"
return {
  "christoomey/vim-tmux-navigator",
  cmd = {
    "TmuxNavigateLeft", "TmuxNavigateDown",
    "TmuxNavigateUp", "TmuxNavigateRight",
  },
  keys = {
    { "<C-h>", "<cmd>TmuxNavigateLeft<cr>" },
    { "<C-j>", "<cmd>TmuxNavigateDown<cr>" },
    { "<C-k>", "<cmd>TmuxNavigateUp<cr>" },
    { "<C-l>", "<cmd>TmuxNavigateRight<cr>" },
  },
}
```

Y en tu `~/.tmux.conf`, el lado de tmux:

```bash title="~/.tmux.conf"
# Navegación consciente de Vim (christoomey/vim-tmux-navigator)
is_vim="ps -o state= -o comm= -t '#{pane_tty}' | grep -iqE '(^|/)g?(view|n?vim?x?)(diff)?$'"
bind-key -n 'C-h' if-shell "$is_vim" 'send-keys C-h' 'select-pane -L'
bind-key -n 'C-j' if-shell "$is_vim" 'send-keys C-j' 'select-pane -D'
bind-key -n 'C-k' if-shell "$is_vim" 'send-keys C-k' 'select-pane -U'
bind-key -n 'C-l' if-shell "$is_vim" 'send-keys C-l' 'select-pane -R'

# Calidad de vida
set -g mouse on
set -g base-index 1
set -g renumber-windows on
setw -g mode-keys vi
```

### Con zellij: zellij-nav + autolock

zellij intercepta las teclas con sus modos. La solución de 2026 combina dos plugins: **zellij-nav** (navegación) y **zellij-autolock** (bloquea zellij automáticamente cuando el panel activo es Neovim, para que no robe las teclas).

```lua title="lua/plugins/zellij-nav.lua"
return {
  "swaits/zellij-nav.nvim",
  lazy = true,
  event = "VeryLazy",
  keys = {
    { "<C-h>", "<cmd>ZellijNavigateLeftTab<cr>", desc = "Nav izquierda" },
    { "<C-j>", "<cmd>ZellijNavigateDown<cr>", desc = "Nav abajo" },
    { "<C-k>", "<cmd>ZellijNavigateUp<cr>", desc = "Nav arriba" },
    { "<C-l>", "<cmd>ZellijNavigateRightTab<cr>", desc = "Nav derecha" },
  },
  opts = {},
}
```

<Callout type="info" title="El truco del autolock">
En zellij, instala también el plugin **zellij-autolock**: detecta cuándo estás en un panel de Neovim y pone zellij en modo "Locked" para que <KeyCap keys="Ctrl-h/j/k/l" /> lleguen a Neovim. Al salir a otro panel, se desbloquea solo. Sin esto, la navegación en zellij es frustrante.
</Callout>

## Sessionizers: saltar entre proyectos

El flujo estrella de los pros: un atajo que abre un selector difuso de proyectos y te crea/abre una sesión para el que elijas.

En **tmux**, el clásico `tmux-sessionizer` (script de ThePrimeagen) con fzf:

```bash title="~/.local/bin/tmux-sessionizer"
#!/usr/bin/env bash
selected=$(find ~/dev ~/work -mindepth 1 -maxdepth 1 -type d | fzf)
[ -z "$selected" ] && exit 0
name=$(basename "$selected" | tr . _)
tmux new-session -ds "$name" -c "$selected" 2>/dev/null
tmux switch-client -t "$name" 2>/dev/null || tmux attach -t "$name"
```

En **zellij**, las sesiones son nativas: `zellij attach --create nombre`, y `Ctrl-o w` abre el gestor de sesiones integrado.

<Callout type="dios" title="El espacio de trabajo definitivo">
Multiplexor + Neovim + sessionizer = cambias de proyecto en una tecla, cada uno con su layout (editor + servidor + tests) intacto y persistente. Navegas entre el editor y los logs con las mismas <KeyCap keys="Ctrl-h/j/k/l" /> sin pensar dónde acaba Neovim y empieza el terminal. Es la sensación de un IDE, pero infinitamente más rápido y tuyo.
</Callout>

<Reto title="Tu espacio persistente">
1. Instala tmux o zellij y configura la navegación transparente.
2. Divide en paneles: editor + terminal. Salta entre ellos con <KeyCap keys="Ctrl-h/j/k/l" /> desde dentro de Neovim.
3. Crea una sesión, ciérrala (detach) y vuelve a entrar (attach): sigue viva.
4. Monta un sessionizer y salta entre dos proyectos con un solo atajo.
</Reto>

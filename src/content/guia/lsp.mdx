## Qué es el LSP

El **Language Server Protocol** separa la inteligencia del lenguaje del editor. Un "language server" (p. ej. `rust-analyzer`, `clangd`, `lua_ls`) es un proceso independiente que entiende tu código y responde preguntas: "¿dónde se define esto?", "¿qué autocompleta aquí?", "¿hay errores?". Neovim es el cliente que le pregunta.

## Mason: el instalador de herramientas

**Mason** instala language servers, formateadores, linters y debuggers sin salir de Neovim. `mason-lspconfig` conecta Mason con la config de LSP y, en su versión actual, **habilita automáticamente** los servidores instalados.

```lua title="lua/plugins/lsp.lua"
return {
  "neovim/nvim-lspconfig",
  event = { "BufReadPre", "BufNewFile" },
  dependencies = {
    { "mason-org/mason.nvim", opts = {} },
    "mason-org/mason-lspconfig.nvim",
    "saghen/blink.cmp",  -- para capabilities (lección 2.2)
  },
  config = function()
    -- 1) Defaults para TODOS los servidores: sumamos las capabilities
    --    de blink.cmp para que el completado sepa qué puede pedir el LSP.
    vim.lsp.config("*", {
      capabilities = require("blink.cmp").get_lsp_capabilities(),
    })

    -- 2) Overrides por servidor (settings específicos)
    vim.lsp.config("lua_ls", {
      settings = {
        Lua = {
          diagnostics = { globals = { "vim" } },   -- reconoce el global `vim`
          workspace = { checkThirdParty = false },
          telemetry = { enable = false },
        },
      },
    })

    -- 3) Mason instala y mason-lspconfig habilita automáticamente
    require("mason-lspconfig").setup({
      ensure_installed = {
        "lua_ls",       -- Lua (tu config)
        "clangd",       -- C / C++
        "ts_ls",        -- TypeScript / JavaScript
        "tailwindcss",  -- Tailwind
        "cssls", "html", "emmet_language_server",
        "jsonls", "yamlls",
      },
    })
  end,
}
```

<Callout type="info" title="Rust y Swift van aparte">
No metas `rust_analyzer` aquí: lo gestiona **rustaceanvim** (lección 2.6) y habría conflicto. Y `sourcekit-lsp` de Swift viene con Xcode, no por Mason (lección 2.7). Cada uno tiene su lección afinada.
</Callout>

## Keymaps de LSP (al conectar)

Los atajos de LSP solo tienen sentido cuando hay un servidor activo en el buffer. El patrón correcto es engancharlos al evento `LspAttach`. Añade esto dentro del `config`:

```lua title="lua/plugins/lsp.lua (dentro de config)"
vim.api.nvim_create_autocmd("LspAttach", {
  group = vim.api.nvim_create_augroup("lsp_attach", { clear = true }),
  callback = function(ev)
    local map = function(keys, fn, desc)
      vim.keymap.set("n", keys, fn, { buffer = ev.buf, desc = "LSP: " .. desc })
    end

    map("gd", vim.lsp.buf.definition, "Ir a definición")
    map("gD", vim.lsp.buf.declaration, "Ir a declaración")
    map("gr", vim.lsp.buf.references, "Referencias")
    map("gi", vim.lsp.buf.implementation, "Implementaciones")
    map("K", vim.lsp.buf.hover, "Documentación flotante")
    map("<leader>rn", vim.lsp.buf.rename, "Renombrar símbolo")
    map("<leader>ca", vim.lsp.buf.code_action, "Code action")
    map("<leader>d", vim.diagnostic.open_float, "Ver diagnóstico")
    map("[d", function() vim.diagnostic.jump({ count = -1 }) end, "Diagnóstico anterior")
    map("]d", function() vim.diagnostic.jump({ count = 1 }) end, "Diagnóstico siguiente")

    -- Inlay hints (tipos inline), si el servidor los soporta
    local client = vim.lsp.get_client_by_id(ev.data.client_id)
    if client and client:supports_method("textDocument/inlayHint") then
      vim.lsp.inlay_hint.enable(true, { bufnr = ev.buf })
      map("<leader>th", function()
        vim.lsp.inlay_hint.enable(not vim.lsp.inlay_hint.is_enabled({ bufnr = ev.buf }), { bufnr = ev.buf })
      end, "Toggle inlay hints")
    end
  end,
})
```

<Callout type="tip" title="0.11 ya trae defaults">
Neovim 0.11 mapea por defecto `grn` (rename), `gra` (code action), `grr` (references) y `K` (hover). Los de arriba son alias más clásicos (`gd`, `gr`...). Usa los que te resulten naturales; lo importante es que existan.
</Callout>

## Diagnósticos con estilo

Configura cómo se ven los errores y avisos. En tu `config`:

```lua title="lua/plugins/lsp.lua (dentro de config)"
vim.diagnostic.config({
  virtual_text = { prefix = "●", spacing = 2 },
  underline = true,
  update_in_insert = false,
  severity_sort = true,
  float = { border = "rounded", source = true },
  signs = {
    text = {
      [vim.diagnostic.severity.ERROR] = " ",
      [vim.diagnostic.severity.WARN]  = " ",
      [vim.diagnostic.severity.HINT]  = " ",
      [vim.diagnostic.severity.INFO]  = " ",
    },
  },
})
```

</PluginCard>

<PluginCard name="trouble.nvim" repo="folke/trouble.nvim" tag="opt" icon="🚑">
Lista bonita y navegable de todos los diagnósticos, referencias y symbols del proyecto. `<leader>xx` para abrirla.
</PluginCard>

<Callout type="dios" title="El comando que resuelve el 90% de los problemas">
Si un servidor no arranca o algo va raro, ejecuta `:checkhealth lsp` y `:LspInfo` (o `:lua vim.lsp.log`). Verás qué servidor está adjunto, la raíz del proyecto detectada y los errores. Antes de buscar en Google, mira ahí: casi siempre es un binario que falta (lo instalas con `:Mason`) o una raíz de proyecto mal detectada.
</Callout>

<Reto title="Enciende el cerebro">
1. Crea `lua/plugins/lsp.lua` con Mason, la config y los keymaps.
2. Abre un archivo `.lua` de tu propia config. Deberías ver diagnósticos si hay errores.
3. Pon el cursor sobre `vim.opt` y pulsa `K`: aparece la documentación.
4. Ejecuta `:Mason` y explora la lista de servidores disponibles.
5. Confirma con `:checkhealth lsp` que `lua_ls` está adjunto.

Con el LSP vivo, en la siguiente lección le damos un buen autocompletado.
</Reto>

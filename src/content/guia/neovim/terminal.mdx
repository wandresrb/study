## Buscar en vez de navegar

En un editor con árbol de archivos, para abrir algo despliegas carpetas hasta encontrarlo. Necesitas saber dónde está. En un proyecto ajeno, o grande, o los lunes, no lo sabes.

Un **picker** invierte eso: escribes trozos del nombre y él encuentra el fichero. No necesitas la ruta, ni el nombre completo, ni el orden correcto de las letras.

```text
escribes:  uspf
encuentra: src/components/UserProfile.tsx
           app/user/profile_form.rb
           test/users/profile_spec.js
```

Eso es **coincidencia difusa**: no busca la cadena `uspf`, busca ficheros donde esas cuatro letras aparezcan **en ese orden**, aunque estén separadas. Y las ordena por cercanía: cuanto más juntas y más cerca del principio de una palabra, más arriba.

<Callout type="dios" title="Por qué esto no es un accesorio">
Cuando llegar a cualquier fichero cuesta menos de un segundo, **dejas de organizar tu trabajo alrededor de lo que tienes abierto**. Se acabó mantener quince pestañas por si acaso, o dejar el árbol ocupando una quinta parte de la pantalla para no perderte.

El árbol de archivos no desaparece porque sea malo: desaparece porque resuelve un problema que ya no tienes.
</Callout>

### Escribir consultas que acierten

Tres hábitos que cambian mucho el resultado:

- **Iniciales de las palabras.** `UserProfile.tsx` se encuentra con `upt` mejor que con `userpro`.
- **Trozos de la ruta.** `comp/user` acota a un directorio sin escribirlo entero.
- **Empieza corto.** Tres o cuatro letras suelen bastar; añade más solo si hay demasiados resultados.

## Las fuentes

Un picker no busca solo ficheros. Es la misma ventana sobre listas distintas, y ahí está su valor: **una sola interfaz para todo**.

<Cards>
  <Card icon="📄" title="Ficheros">
    Los del proyecto, respetando `.gitignore`. El que más usarás.
  </Card>
  <Card icon="🔎" title="Grep">
    Busca **texto** en todo el proyecto, no nombres. Es `ripgrep` por debajo.
  </Card>
  <Card icon="🗂️" title="Buffers">
    Lo que ya tienes abierto. Sustituye a las pestañas.
  </Card>
  <Card icon="🕘" title="Recientes">
    Ficheros de sesiones anteriores. «Eso que tocaba ayer.»
  </Card>
  <Card icon="🔣" title="Símbolos">
    Funciones y clases del fichero o del proyecto, vía LSP.
  </Card>
  <Card icon="⚠️" title="Diagnósticos">
    Todos los errores y avisos del proyecto en una lista.
  </Card>
</Cards>

La distinción entre **ficheros** y **grep** es la que más cuesta interiorizar y la más rentable: si sabes cómo se llama, ficheros; si recuerdas una línea de código pero no dónde estaba, grep. La segunda es la que sustituye a leerse el proyecto.

## Operar dentro del picker

Un picker se abre en modo Insertar, porque lo primero que haces siempre es escribir. Lo que viene después es lo que casi nadie aprende:

| Qué quieres | Cómo |
|---|---|
| Bajar y subir por la lista | <KeyCap keys="Ctrl-n" /> / <KeyCap keys="Ctrl-p" /> |
| Abrir | <KeyCap keys="Enter" /> |
| Abrir en split vertical | <KeyCap keys="Ctrl-v" /> |
| Abrir en split horizontal | <KeyCap keys="Ctrl-s" /> |
| Desplazar la **vista previa** | <KeyCap keys="Ctrl-d" /> / <KeyCap keys="Ctrl-u" /> |
| Marcar varios | <KeyCap keys="Tab" /> |
| Mandar todo a la quickfix | <KeyCap keys="Ctrl-q" /> |
| Cerrar | <KeyCap keys="Esc" /> |

<Callout type="tip" title="Compruébalas en tu picker, no te fíes de una tabla">
Cada picker trae sus propias teclas y son configurables. La forma de verlas es abrirlo y consultar su ayuda —en snacks, con <KeyCap keys="?" /> dentro del picker—. Ese reflejo vale para cualquier plugin con interfaz propia: la lista de teclas está dentro, no en un tutorial.
</Callout>

### La tecla que lo conecta con el resto del editor

De todas, la importante es **mandar los resultados a la quickfix**.

Un picker enseña coincidencias de una en una y se cierra al elegir. La quickfix es una lista **persistente** que puedes recorrer, y sobre la que puedes ejecutar un comando en cada entrada con `:cdo`.

```text
grep "getUserData"   →   47 coincidencias en el picker
Ctrl-q               →   las 47 en la quickfix
:cdo s/getUserData/fetchUser/g | update
```

Buscas con el picker, revisas, y renombras en 47 ficheros con una línea. El picker encuentra; la quickfix opera. Eso está en la lección 4.4, y esta tecla es el puente.

## Montarlo

Usaremos **snacks.nvim**: además del picker trae explorador, terminal, dashboard y notificaciones, así que sustituye a media docena de plugins con una sola dependencia.

<Instalar repo="folke/snacks.nvim" nota="snacks tiene que estar cargado desde el arranque (dashboard, notifier, quickfile), así que aquí vim.pack encaja perfecto: sin spec, sin evento y sin prioridad que ajustar. Ojo, cada módulo se activa explícitamente: lo que no aparece en el setup, no existe.">
<Fragment slot="lazy">

```lua title="lua/plugins/snacks.lua"
return {
  "folke/snacks.nvim",
  priority = 1000,
  lazy = false,
  opts = {
    picker = { enabled = true },
    explorer = { enabled = true },
    dashboard = { enabled = true },
    indent = { enabled = true },
    notifier = { enabled = true },
    quickfile = { enabled = true },
  },
  keys = {
    { "<leader>ff", function() Snacks.picker.files() end, desc = "Buscar archivos" },
    { "<leader>fg", function() Snacks.picker.grep() end, desc = "Grep en el proyecto" },
    { "<leader>fb", function() Snacks.picker.buffers() end, desc = "Buffers abiertos" },
    { "<leader>fr", function() Snacks.picker.recent() end, desc = "Archivos recientes" },
    { "<leader>fs", function() Snacks.picker.lsp_symbols() end, desc = "Símbolos del archivo" },
    { "<leader>fd", function() Snacks.picker.diagnostics() end, desc = "Diagnósticos" },
    { "<leader>fh", function() Snacks.picker.help() end, desc = "Ayuda" },
    { "<leader>e",  function() Snacks.explorer() end, desc = "Explorador de archivos" },
  },
}
```

Todo cuelga de `<leader>f` —de *find*— y por eso which-key te lo agrupa solo. Es el presupuesto de teclas de la lección 1.1 aplicado: un prefijo, una familia.

<Callout type="tip" title="Los tres que vas a usar el 90% del tiempo">
`<leader>ff` para ficheros, `<leader>fg` para texto y `<leader>fb` para buffers. Interiorízalos antes de tocar los demás.

Y `<leader>fh`, la ayuda, es el que convierte la lección 0.6 en un reflejo: buscar en la documentación con el mismo gesto con el que buscas un fichero.
</Callout>

## El explorador es secundario

`<leader>e` abre el árbol, y merece la pena tenerlo: para ver la forma de un proyecto que no conoces, para crear y renombrar ficheros, para arrastrar cosas de sitio.

Lo que no merece la pena es **dejarlo abierto**. Ocupa pantalla permanentemente para resolver algo que el picker resuelve en un segundo. Ábrelo cuando lo necesites y ciérralo.

## Telescope y fzf-lua

Son las otras dos opciones serias, y no se mencionan aquí de pasada para que quede constancia.

**Telescope** fue el estándar durante años y tiene el ecosistema de extensiones más grande. **fzf-lua** delega la coincidencia difusa al binario `fzf`, y en repositorios enormes se nota. **snacks** es el más nuevo y el que menos dependencias arrastra si ya lo usas para lo demás.

Los tres hacen lo mismo desde tu punto de vista: escribir, filtrar, elegir. **Lo que aprendes en esta lección no es snacks, es el picker**, y se transfiere entero si algún día cambias. Elegimos uno porque un curso no puede montar tres, no porque los otros dos estén mal.

<Reto title="Deja de abrir el árbol">
Durante un día entero, prohíbete el explorador. Todo con el picker:

1. Abre cinco ficheros que no recuerdes dónde están, solo con `<leader>ff`.
2. Busca una cadena de texto por todo el proyecto con `<leader>fg` y salta a tres coincidencias distintas.
3. Vuelve a un fichero de ayer con `<leader>fr`.
4. Manda un grep entero a la quickfix con <KeyCap keys="Ctrl-q" /> y recórrelo con `:cnext`.
5. Abre la ayuda de `'signcolumn'` con `<leader>fh` en vez de escribir `:h`.

Al final del día habrás dejado de pensar en dónde están las cosas, que es exactamente el objetivo.
</Reto>

<Lead>
Swift en Neovim es totalmente viable en macOS. El servidor de lenguaje, sourcekit-lsp, viene con la toolchain de Swift/Xcode. El truco está en que encuentre cómo se compila tu proyecto — trivial con SPM, un paso extra con Xcode.
</Lead>

<Objetivos>

- Habilitar sourcekit-lsp (viene con Xcode, no con Mason).
- Proyectos SPM vs proyectos Xcode.
- Generar `buildServer.json` con xcode-build-server.
- Formateo con swift-format y gestión de toolchains.

</Objetivos>

<Callout type="warn" title="Esto es territorio macOS">
sourcekit-lsp funciona mejor en macOS con Xcode instalado. En Linux funciona con la toolchain de Swift, pero sin las APIs de Apple. Como desarrollas Swift, asumimos macOS con las Command Line Tools de Xcode.
</Callout>

## Habilitar sourcekit-lsp

sourcekit-lsp **no** se instala por Mason: ya viene con la toolchain. Solo hay que habilitarlo. `nvim-lspconfig` trae la config; la activamos:

```lua title="lua/plugins/lang-swift.lua"
return {
  "neovim/nvim-lspconfig",
  opts = function()
    vim.lsp.config("sourcekit", {
      cmd = { "xcrun", "sourcekit-lsp" },
      filetypes = { "swift", "objc", "objcpp", "c", "cpp" },
      root_markers = { "Package.swift", ".git", "buildServer.json" },
    })
    vim.lsp.enable("sourcekit")
  end,
}
```

<Callout type="info" title="Comprueba la toolchain">
Verifica que la tienes con `xcrun sourcekit-lsp --help` y `swift --version` en el terminal. Si falla, instala las herramientas con `xcode-select --install` o abre Xcode una vez para que termine de configurarse.
</Callout>

## SPM: funciona directo

En un paquete de **Swift Package Manager** (con `Package.swift` en la raíz), sourcekit-lsp funciona sin más: abre cualquier `.swift` y tendrás completado, ir a definición y diagnósticos. Es el caso ideal.

## Proyectos Xcode: xcode-build-server

Para proyectos `.xcodeproj` / `.xcworkspace`, sourcekit-lsp necesita un `buildServer.json` que le explique el grafo de compilación. Lo genera **xcode-build-server**:

```bash
# Instalar
brew install xcode-build-server

# En la raíz del proyecto, para un esquema concreto:
xcode-build-server config -scheme MiApp -project MiApp.xcodeproj
# o para un workspace:
xcode-build-server config -scheme MiApp -workspace MiApp.xcworkspace
```

Esto crea `buildServer.json`. Reinicia Neovim y sourcekit-lsp ya entenderá tu proyecto Xcode (frameworks, targets, etc.).

<Callout type="tip" title="Compilar y correr sin salir de Neovim">
Para lanzar builds, simuladores y tests de Xcode desde Neovim, mira **xcodebuild.nvim** (`wojciech-kulik/xcodebuild.nvim`): integra `xcodebuild`, gestión de simuladores, y hasta debugging con nvim-dap. Es lo más cercano a un "Xcode sin Xcode".
</Callout>

## Formateo con swift-format

Ya declaraste `swift = { "swift_format" }` en conform. En toolchains recientes, `swift-format` viene incluido (`swift format ...`); si no, instálalo con `brew install swift-format`. Personaliza con un `.swift-format` (JSON) en la raíz:

```json title=".swift-format"
{
  "version": 1,
  "lineLength": 100,
  "indentation": { "spaces": 4 }
}
```

## Gestionar toolchains con swiftly

Si necesitas varias versiones de Swift, **swiftly** (el gestor oficial de toolchains) te deja cambiar entre ellas:

```bash
swiftly install latest
swiftly use 6.0.0
```

<Callout type="dios" title="Expectativas realistas">
El ecosistema Swift en Neovim es más pequeño que el de Rust o el frontend, y sourcekit-lsp puede tardar en indexar proyectos Xcode grandes. Aun así, para editar Swift —SwiftUI, paquetes SPM, lógica de servidor— tienes completado, navegación, diagnósticos, formateo y debugging. Para builds de apps complejas, xcodebuild.nvim cubre el hueco. Es un setup productivo de verdad.
</Callout>

<Reto title="Swift funcionando">
1. Confirma `xcrun sourcekit-lsp --help` en el terminal.
2. Abre un paquete SPM y verifica completado con `K` y `gd`.
3. En un proyecto Xcode, genera `buildServer.json` con xcode-build-server y reinicia.
4. Guarda un `.swift` mal indentado y comprueba que swift-format lo arregla.
</Reto>

<Lead>
Un plugin es solo código Lua que Neovim carga. Un gestor de plugins los descarga, los actualiza y —lo más importante— los carga de forma perezosa para que Neovim arranque en milisegundos. Vamos a montar el estándar del ecosistema.
</Lead>

<Objetivos>

- Entender la diferencia entre `vim.pack` (nativo) y `lazy.nvim`.
- Instalar y arrancar (bootstrap) `lazy.nvim`.
- Estructurar tus plugins en archivos separados.
- Añadir tus primeros tres plugins: tema, Treesitter y which-key.

</Objetivos>

## vim.pack vs lazy.nvim

Neovim 0.12 trae un gestor **nativo**, `vim.pack`. Es excelente para setups minimalistas:

```lua
-- Ejemplo de vim.pack (nativo, sin dependencias)
vim.pack.add({
  { src = "https://github.com/catppuccin/nvim" },
  { src = "https://github.com/nvim-treesitter/nvim-treesitter" },
})
```

Entonces, ¿por qué esta guía usa **lazy.nvim**? Porque para un IDE completo necesitas cosas que lazy da y pack todavía no iguala:

<Cards>
  <Card icon="🦥" title="Lazy-loading fino">
    Carga plugins por evento, comando, tipo de archivo o tecla. Arranque por debajo de 50 ms con 40+ plugins.
  </Card>
  <Card icon="🔒" title="Lockfile">

  </Card>
  <Card icon="🎛️" title="UI de gestión">

  </Card>
  <Card icon="🧩" title="Ecosistema">
    Casi toda la documentación y ejemplos de 2026 asumen lazy.nvim. Es el estándar de facto.
  </Card>

<Callout type="tip" title="Regla práctica">
¿Config pequeña y personal, pocos plugins? `vim.pack` te sobra. ¿Quieres el IDE completo de esta guía con C/Rust/Swift/frontend? `lazy.nvim`. Iremos con lazy.
</Callout>

## Bootstrap de lazy.nvim

"Bootstrap" = que la config se auto-instale el gestor la primera vez. Crea `lua/config/lazy.lua`:

```lua title="lua/config/lazy.lua"
-- Clona lazy.nvim si no existe
local lazypath = vim.fn.stdpath("data") .. "/lazy/lazy.nvim"
if not (vim.uv or vim.loop).fs_stat(lazypath) then
  local repo = "https://github.com/folke/lazy.nvim.git"
  vim.fn.system({ "git", "clone", "--filter=blob:none", "--branch=stable", repo, lazypath })
end
vim.opt.rtp:prepend(lazypath)

-- Arranca lazy cargando TODOS los archivos de lua/plugins/
require("lazy").setup({
  spec = { { import = "plugins" } },
  install = { colorscheme = { "catppuccin" } },
  checker = { enabled = true, notify = false }, -- avisa de actualizaciones
  ui = { border = "rounded" },
})
```

Ahora descomenta `require("config.lazy")` en tu `init.lua`. Con `{ import = "plugins" }`, lazy cargará automáticamente **cada archivo** dentro de `lua/plugins/`. Cada archivo devuelve una "spec": una tabla que describe uno o varios plugins.

<Callout type="info" title="Anatomía de una spec">
Una spec mínima es `{ "autor/repo" }`. Las claves útiles: `opts` (opciones que se pasan al `setup` del plugin), `config` (función de configuración), `event`/`ft`/`cmd`/`keys` (cuándo cargarlo, para lazy-loading), y `dependencies`.
</Callout>

## Plugin 1: el tema (Catppuccin)

Crea `lua/plugins/colorscheme.lua`:

```lua title="lua/plugins/colorscheme.lua"
return {
  "catppuccin/nvim",
  name = "catppuccin",
  priority = 1000,          -- carga antes que el resto (es el tema)
  config = function()
    require("catppuccin").setup({
      flavour = "mocha",      -- latte, frappe, macchiato, mocha
      integrations = {
        treesitter = true,
        native_lsp = { enabled = true },
        which_key = true,
        gitsigns = true,
      },
    })
    vim.cmd.colorscheme("catppuccin")
  end,
}
```

Guarda, reinicia Neovim y lazy instalará Catppuccin automáticamente. Tu editor ya no es gris.

## Plugin 2: Treesitter

Treesitter da resaltado de sintaxis **semántico** (entiende la estructura, no solo patrones) y habilita objetos de texto inteligentes. Crea `lua/plugins/treesitter.lua`:

```lua title="lua/plugins/treesitter.lua"
return {
  "nvim-treesitter/nvim-treesitter",
  build = ":TSUpdate",
  event = { "BufReadPost", "BufNewFile" },  -- lazy: al abrir un archivo
  config = function()
    require("nvim-treesitter.configs").setup({
      ensure_installed = {
        "lua", "vim", "vimdoc",
        "c", "rust", "swift",
        "javascript", "typescript", "tsx", "html", "css",
        "json", "yaml", "toml", "markdown", "bash",
      },
      highlight = { enable = true },
      indent = { enable = true },
      incremental_selection = { enable = true },
    })
  end,
}
```

<PluginCard name="nvim-treesitter" repo="nvim-treesitter/nvim-treesitter" tag="core" icon="🌳">
Motor de parsing incremental. Base del resaltado moderno y de la edición por estructura. Lo exprimimos en el Nivel 2.
</PluginCard>

## Plugin 3: which-key

Aquí ves el fruto de haber puesto `desc` en cada keymap. which-key muestra un menú flotante con tus atajos al pulsar `<leader>`. Crea `lua/plugins/which-key.lua`:

```lua title="lua/plugins/which-key.lua"
return {
  "folke/which-key.nvim",
  event = "VeryLazy",   -- carga tras el arranque, sin frenar el inicio
  opts = {
    preset = "modern",
  },
}
```

Reinicia, pulsa `<leader>` (espacio) y espera medio segundo: aparece el menú con todo lo que configuraste. Nunca más olvidarás un atajo.

<PluginCard name="which-key.nvim" repo="folke/which-key.nvim" tag="core" icon="⌨️">
Descubre y recuerda atajos. Imprescindible cuando tu config crece. Lee los `desc` de tus keymaps.
</PluginCard>

## El flujo de trabajo con lazy

<div class="pill-row">
  <span class="pill"><b>:Lazy</b> abre el panel de gestión</span>
  <span class="pill"><b>:Lazy sync</b> instala + actualiza + limpia</span>
  <span class="pill"><b>:Lazy update</b> actualiza plugins</span>
  <span class="pill"><b>:Lazy profile</b> mide el arranque</span>
</div>

<Callout type="dios" title="Un archivo por plugin">
Mantén la disciplina de **un archivo por plugin** (o por grupo lógico) en `lua/plugins/`. Añadir una herramienta será crear un archivo; quitarla, borrarlo. Tu config se mantiene navegable aunque llegue a 50 plugins. Así está construida la [config completa](/config/) de referencia.
</Callout>

<Reto title="Tu primer setup con plugins">
1. Monta el bootstrap de lazy y descoméntalo en `init.lua`.
2. Añade los tres plugins (tema, Treesitter, which-key).
3. Reinicia, deja que lazy instale, y ejecuta `:Lazy` para ver el panel.
4. Pulsa `<leader>` y confirma que which-key muestra tus atajos.
5. Ejecuta `:Lazy profile` y mira cuánto tarda en arrancar (debería ser < 100 ms).

Con esto dominas el ciclo instalar → configurar → cargar. En el Nivel 2 lo usaremos para construir el IDE.
</Reto>

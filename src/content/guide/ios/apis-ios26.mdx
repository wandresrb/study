## Toolbars que se adaptan

Antes, cuando la pantalla se estrechaba, los botones de la toolbar se apretujaban o desaparecían sin control. iOS 26 da control fino:

```swift
.toolbar {
    ToolbarItemGroup {
        Button("Compartir", systemImage: "square.and.arrow.up") { }
            .toolbarOverflowMenu()          // va al menú "…" si no cabe
    }
}
.toolbar {
    Button("Guardar", systemImage: "checkmark") { }
        .visibilityPriority(.high)          // se mantiene visible más tiempo
}
```

## Contenedores reordenables

Una de las mejores novedades: reordenar arrastrando ya no es exclusivo de `List` ni requiere código especial. La misma API funciona en `List`, `LazyVGrid` y más:

```swift
@State private var items = ["Uno", "Dos", "Tres"]

List {
    ForEach(items, id: \.self) { Text($0) }
        .onMove { origen, destino in
            items.move(fromOffsets: origen, toOffset: destino)
        }
}
```

Y ahora la reordenación llega incluso a contenedores como grids con el mismo código — antes impensable sin implementarlo a mano.

## La API de documentos

Para apps basadas en documentos (editores, notas), la nueva API da control directo sobre cómo se leen y escriben en disco, de forma **asíncrona e incremental** con reporte de progreso:

```swift
struct MiDoc: WritableDocument, ReadableDocument {
    var texto: String
    // lectura/escritura asíncrona con Subprogress para mostrar progreso
}
```

Conforma a `WritableDocument` y `ReadableDocument` y obtienes operaciones de disco no bloqueantes, ideales para archivos grandes.

## AsyncImage con caché

`AsyncImage` carga imágenes de una URL, pero hasta ahora las recargaba al hacer scroll. En iOS 26 cachea automáticamente vía HTTP:

```swift
AsyncImage(url: URL(string: "https://ejemplo.com/foto.jpg")) { imagen in
    imagen.resizable().scaledToFill()
} placeholder: {
    ProgressView()
}
```

Ahora, al desplazar una lista de imágenes arriba y abajo, no se vuelven a descargar: el caché HTTP las conserva. Menos datos, scroll más fluido, sin librerías externas.

<Callout type="dios" title="Mantente al día, pero sin correr detrás de cada novedad">
Cada versión de iOS trae APIs nuevas, y es tentador reescribir todo para usarlas. La postura sensata: **conoce** lo nuevo (para no reinventar lo que ya resuelve el sistema) pero **adopta** según tu público. Si soportas iOS 25, no puedes usar aún lo de iOS 26 sin un fallback. Las novedades de esta lección son sólidas y las usarás en proyectos nuevos; en apps con base de usuarios amplia, comprueba siempre tu versión mínima antes. Saber qué existe es la mitad del trabajo; saber cuándo usarlo es la otra mitad.
</Callout>
